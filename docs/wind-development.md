# 风电项目监控开发说明

## v0.1 的边界

已完成项目底表和证据闭环，为固定信源监控接上独立队列。可以用已配置来源和已入库正文产生候选，尚无完整互联网发现能力。公开新闻模块保留上游分类和提示词，尚未校准成风电资讯产品；开发库关闭采集和模型调用，公开页面不是首版入口。

后台入口 `/admin/projects`。网页只调用 API，数据库访问与规则处理留在后端。

## 数据与事务

- `wind_projects`：稳定 ID、底表参考属性、别名、版本。预览令牌包含输入和现存版本，提交事务锁定后重新校验。
- `wind_evidence`：网址与正文哈希唯一；同网址变更另存快照，旧证据不覆盖。发布日期与发现时间分开保存。
- `wind_candidates`：字段、值、事件日期、计划标记、范围、原句和归属。含糊归属须审核者明确指定。
- `wind_changes`：不可变确认记录，保留前后值、原因、操作者、确认时间和证据。重复同一审核幂等，相反决定拒绝。
- `wind_facts`：项目、字段、范围的当前事实。确认事务比较项目版本；旧日期或未知日期不能覆盖已知较新事实。更正需显式选择并审计。
- `wind_source_targets`：项目与来源绑定；检查成功不等于全网覆盖。
- `wind_article_runs`：正文处理记录与文章版本。输入哈希包含底表与规则版本，新增别名可重扫已有材料。

增量迁移 `0039_wind_projects.sql`、`0040_wind_run_revision.sql` 不改写上游业务数据。演示数据只有显式执行脚本才写入，不在迁移中自动插入。

## 处理链路

```text
已有采集器 → 文章入库 → 提取正文 → wind.monitor → 候选 → 人工审核
                                               ↑          ↓
人工粘贴公告 / 附件文字 ────────────────────────┘   当前事实 + 历史
                                                          ↓
                                                    内部简报 / CSV
```

绑定的隔离信源也进入正文和风电队列；候选不受新闻预筛、热度、评分、发布时间窗口或公开发布限制。worker 每五分钟补扫现有材料；关闭采集时仍能处理已入库文章。扫描每批最多 100 篇，运行记录与缺正文状态在后台可见。

规则只识别包含明确项目名或别名的句子；项目名自带的“一期”不会被误认为额外标段。另有分期或标段则单独存范围。计划表述只产生计划并网日期，不能升级实际并网；否定表述保守跳过。跨段归属、主体变更等复杂情况需要人工候选或下一版模型抽取，规则未识别不表示没有变化。

## 下一轮顺序

1. 导入用户的真实底表，确认分期、ID、主体与别名；广东海上风电小范围试点目前只是默认建议。
2. 逐个验证第一批官方来源的列表、正文、附件和更新时间；建立真实正反样本，记录漏抓与解析失败。
3. 接入附件文本提取与模型结构化抽取。模型仅在 worker 调用，沿用回执和预算机制；引用必须定位回快照，复杂范围与低置信归属进入复核。
4. 增加未配置、连续失败、缺正文、过期复核告警，再接主动搜索。搜索工具只是发现渠道，原始发布者仍是来源主体。
5. 增加内部通知事务发件箱、幂等推送、失败重试，再接周报及经过授权的私有查询 API/MCP。
6. 用真实标注集校准匹配、抽取、迁移与通知效果。公开新闻分类、评分与条款另行校准和完成上线准备。

未接真实底表、来源与模型前不能评价全网召回率，也不能用演示结果证明生产效果。当前没有外部推送，所有实际事实须复核后入账。

## 历史资料接入

迁移 `0041_wind_history.sql` 保存独立历史档案及多项目关联。原始正文与来源 ID 不可变，重复导入返回 repeated；相同 ID 内容变化拒绝整批事务，防止旧档案被覆盖。来源邮件时间、事件日期和导入时间分别保存，未知的历史会话时间不推测。

Gmail SENT 只表示存在发送记录，不证明已投递或已读；会话自称已发送为未知，报告明确未发送则保留其记载。导入不调用通知队列，不产生新事实，不把历史摘要冒充官方原文。中标候选人、公示、跨项目采购、政策和项目名未披露记录均完整保留在档案，不强行归属。

历史项目匹配只使用事件里的项目提示及底表登记名称/别名；支持暂停项目与一份记录关联多个项目。人工关联（包括清空关联）不会被后续自动匹配覆盖。项目详情提供对应历史档案入口，后续补齐真实底表后重新匹配即可。
